# CV-Агент

A local job-search assistant for the German job market, built with Python,
Flask and SQLite. It aggregates vacancies, compares them with candidate documents,
generates cover-letter drafts and prepares application dossiers for manual submission.
Supports local Ollama and external LLM providers, isolated family profiles,
background jobs and an experimental rule/embedding scoring engine.

Агент для поиска и оценки вакансий, генерации сопроводительных писем (Anschreiben) и подготовки досье для подачи заявок на немецком рынке труда. Полуавтоматический: вакансии ищутся и оцениваются автоматически, отправка заявки выполняется вручную.

## Возможности

- **Поиск вакансий** — Arbeitsagentur, StepStone, LinkedIn и get-in-it: нормализованные account keywords, раздельные лимиты на запрос и весь прогон, локальный geo-filter для get-in-it и дедупликация с уже сохранёнными вакансиями.
- **Проверка актуальности** — повторный поиск обновляет source-поля без потери score/application status. Недоступная BA-вакансия архивируется, но не удаляется; активные вакансии повторно используют description cache.
- **Оценка вакансий (LLM)** — вакансия с содержательным описанием сравнивается с документами текущего профиля: сохраняются балл 0–100, причины, недостающие требования, модель и хэши входов. Неизменённые входы повторно не оцениваются.
- **Сопроводительные письма** — генерация индивидуального Anschreiben на немецком языке под конкретную вакансию.
- **Досье** — сборка папки с сопроводительным, CV (PDF) и описанием вакансии для ручной отправки.
- **Семейные профили без паролей** — вакансии, документы, ключевые слова и Gemini key разделены между профилями; переключение остаётся свободным, так как приложение предназначено только для локального использования.
- **Веб-интерфейс** (на русском) — запуск pipeline, просмотр результатов и управление PDF/TXT/MD-документами.

## Установка

Требуется Python 3.10+.

```bash
./run.sh                        # создаст .venv и установит зависимости при первом запуске
```

Или вручную:

```bash
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
```

### Настройка LLM

Основной provider — локальная Ollama. Её адрес можно задать в `.env` (см. `.env.example`):

```
OLLAMA_HOST=localhost:11434
```

Ключ внешнего провайдера вводится на странице профиля и не возвращается обратно в HTML. При выборе внешней модели или автоматическом fallback на неё текст документов и вакансий передаётся соответствующему провайдеру без дополнительного подтверждения. Для локальной обработки используйте Ollama и отключите `llm_fallback` в конфигурации.

## Конфигурация

### `criteria.yaml` — критерии поиска

| Поле | Описание |
|---|---|
| `region` | Место поиска (PLZ + город) |
| `radius_km` | Радиус поиска |
| `limits` | Межпроцессные лимиты: общий `network_concurrency` и отдельный `llm_backend_concurrency` для каждого LLM backend |
| `keywords` | Ключевые слова — по каждому выполняется отдельный запрос |
| `search` | `max_keywords`, `per_query_limit`, общий `total_limit`, `similarity_threshold`, `description_ttl_hours` и необязательный список `getinit_categories` |
| `exclusions` | Отдельные `words`/`regex` для `title`, `company` и `description`; слова совпадают целиком (`Sales` не совпадает с `Salesforce`) |
| `min_score` | Единый минимальный балл для результатов; вакансия с равным баллом включается |
| `llm` | Настройки LLM: `provider`, `model`, `base_url`, `api_key_env` (имя переменной окружения с ключом), `temperature` |

### Документы и `profile.yaml`

Основной источник для оценки и писем — документы текущего профиля (PDF с
текстовым слоем, UTF-8 TXT и MD). На странице профиля для каждого файла видны
тип, объём извлечённого текста, объём следующего scoring-контекста и понятная
ошибка, если PDF требует OCR. Тип `Lebenslauf` можно назначить вручную; такой
документ получает приоритет перед curriculum и дополнительными файлами.
`profile.yaml` используется как legacy fallback, если документы отсутствуют или
не извлекаются; обезличенный формат показан в `profile.example.yaml`.

## Использование

### Веб-интерфейс (рекомендуется)

```bash
./run.sh web
```

Откройте http://127.0.0.1:8000

- **Выбор профиля** — dropdown существующих профилей и создание нового. Пароля нет намеренно: профиль разделяет данные, а не защищает их от членов семьи.
- **Вакансии** (главная) — запуск поиска (`keywords` при необходимости, затем `search` и `score` с живым прогрессом) с общим лимитом и необязательным Orts-фильтром: в каждое поле (страна/регион/город) можно ввести несколько значений через запятую, например `Bayern, Baden-Württemberg`; заполненное поле ограничивает выдачу, самое конкретное из заполненных побеждает; таблица всех вакансий (сортировка по баллу), просмотр описания вакансии с переводом по POST-запросу, список собранных досье.
- **Профиль** — отдельные полное имя, контакты, языки, язык Anschreiben, регион поиска, документы и Gemini key; политика удаления профиля: архив-экспорт → подтверждённое удаление.

Web UI по умолчанию слушает только loopback. Не задавайте `CV_AGENT_HOST` для доступа из недоверенной сети: в проекте нет парольной аутентификации. При намеренном HTTPS-развёртывании установите `CV_AGENT_SESSION_SECURE=1`.

Если порт 8000 занят (например, системным сервисом didiwiki):

```bash
CV_AGENT_PORT=8011 ./run.sh web
```

### Командная строка

```bash
./run.sh search --total-limit 100 --per-query-limit 25 --max-keywords 12
# --limit остаётся совместимым псевдонимом --total-limit
./run.sh score --verbose     # оценка только новых или изменившихся входов
./run.sh score --force       # принудительная переоценка всех подходящих вакансий
./run.sh write <refnr>       # сопроводительное письмо для одной вакансии
./run.sh apply <refnr>       # досье (письмо + CV + stelle.txt), статус prepared
./run.sh confirm-applied <refnr>  # подтвердить ручную отправку (prepared → applied)
./run.sh status              # список сохранённых вакансий
./run.sh status --archived   # архив с source status и датой архивирования
./run.sh purge-archived --confirm --older-than-days 30  # старый архив, кроме applied
./run.sh prune-jobs --confirm --older-than-days 30      # retention фоновых заданий
./run.sh migrate-storage     # read-only план перехода на UUID-каталоги
./run.sh migrate-storage --apply  # backup + копирование + активация нового layout
```

После `apply` вакансия получает статус **prepared**; **applied** ставится
только вашим подтверждением (команда выше или кнопка на странице вакансии) —
так приложение не путает «досье готово» и «отправлено». Повторный `apply`
заменяет существующее досье после успешной сборки; старые каталоги `_vN`
удаляются. Перед повторной генерацией сохраните отдельно нужную версию.

Референсный номер (`refnr`) берётся из вывода `status` (первая колонка) или из таблицы на странице результатов.

### Порядок работы

1. `search` — найти и сохранить вакансии
2. `score` — оценить их (балл 0–100)
3. `write` / `apply` — для лучших вакансий

## Хранение данных

- **SQLite**: `data/applications.db` — версионируемая схема; технические accounts отделены от структурированных данных кандидата, вакансии и фоновые прогоны имеют FK на `account_id`, баллы, статусы, шаги, ограниченные логи и метрики ожидания network/LLM pools. Одновременно может выполняться по одному прогону на профиль; чужой `run_id` из другого профиля не открывается. Перед изменением старой схемы автоматически создаётся консистентный backup в `data/backups/`.
- **Документы и новые досье после миграции**: `data/accounts/<account_id>/{cv,applications,tmp}/`
- **Legacy storage до миграции**: `cv/<имя профиля>/` и общий `applications/`. Безопасный порядок перехода и восстановления описан в `docs/STORAGE_MIGRATION.md`.
- **Каталог данных**: по умолчанию каталог проекта; переопределяется переменной `CV_AGENT_DATA_DIR` (создаётся с правами 0700).
- **Health**: `GET /health` — состояние DB, версии схемы, активных заданий и Ollama (без секретов, без входа).
- **Журнал заданий**: `data/logs/jobs.jsonl` — структурные события прогонов (start/step/finish) с redaction секретов.

В карточке вакансии под описанием и переводом есть блок **«Ваша оценка вакансии»**:
«Подходит», «Сомнительно», «Не подходит» и необязательное пояснение.
Нажатие сохраняет выбранную оценку вместе с пояснением. Можно изменить ответ,
сохранить только пояснение или убрать свою оценку. Отзывы относятся только к
текущему профилю и не меняют автоматический балл. При изменении исходных данных
карточка предложит повторную проверку. Оценивать все вакансии не обязательно.

## Известные ограничения

- Внешние сайты вакансий могут менять HTML или ограничивать guest-доступ; StepStone, LinkedIn и get-in-it работают в режиме best-effort, основной источник — Arbeitsagentur.
- Лимиты внешнего LLM зависят от провайдера и тарифа; при ответе 429 клиент выполняет ограниченные повторы с ожиданием.
- Фоновый прогон выполняется отдельным процессом `cv_agent.job_worker`, а состояние и ограниченный лог хранятся в SQLite. Аварийный выход worker помечает job как `failed`; после перезапуска оставшийся active job становится `interrupted`, и его можно запустить снова. Дочерние CLI-процессы имеют wall-clock deadline; при зависании выполняется `terminate`, затем `kill` и обязательный reap.
- Подача заявок выполняется вручную: досье готовится, но не отправляется.
