# ADR-004: локальный LLM и контролируемый внешний fallback

- Статус: Accepted
- Дата: 20.08.2026

> Обновление: требование отдельного подтверждения ниже описывает исходное
> решение. В текущем UI оно отменено: выбранная внешняя модель и настроенный
> fallback используются без дополнительного подтверждения. Актуальное
> поведение описано в `docs/PRIVACY.md`.

## Контекст

Документы кандидата содержат персональные данные. Основной backend — локальная
Ollama, но при её недоступности приложение может автоматически перейти на
Gemini. Текущая LLM cookie позволяет клиенту задавать произвольный endpoint, а
account key попадает в process environment.

## Решение

- Ollama остаётся провайдером по умолчанию.
- UI хранит только ID варианта из server-side allowlist.
- `base_url`, model mapping и способ получения ключа определяет серверная
  конфигурация; произвольный endpoint из cookie/form запрещён.
- API key передаётся конкретному `LLMClient` явно и не записывается в глобальный
  `os.environ` во время web-запроса.
- Gemini key хранится отдельно для каждого профиля и не отображается целиком.
- Перед отправкой CV внешнему fallback UI показывает фактического провайдера и
  требует явное подтверждение политики передачи данных. Решение можно запомнить
  в настройках конкретного профиля.
- Результат job фиксирует фактически использованные provider/model, не сохраняя
  секрет.
- Логи редактируют API keys и полный текст документов.

## Последствия

- Автоматический незаметный переход с локальной обработки на внешнюю исчезает.
- Подмена cookie не превращает приложение в SSRF/client-secret relay.
- При недоступной Ollama некоторые jobs будут ждать решения пользователя вместо
  немедленного fallback.
