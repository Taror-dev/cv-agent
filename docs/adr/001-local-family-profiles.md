# ADR-001: локальные семейные профили без паролей

- Статус: Accepted
- Дата: 20.08.2026

## Контекст

Приложение запускается локально и используется владельцем и его семьёй.
Профили нужны, чтобы не смешивать вакансии, документы, API-ключи, задания и
досье разных кандидатов. Члены семьи являются доверенными пользователями и
могут намеренно переключаться между профилями.

Текущая cookie содержит отображаемое имя и используется одновременно как
идентификатор БД и компонент файлового пути. Это создаёт ошибки изоляции и
path traversal даже без недоверенного пользователя.

## Решение

- Пароли, роли, password reset и запрет доступа к профилю не реализуются.
- Страница выбора профиля остаётся доступной без пароля.
- Активный профиль хранится как неизменяемый `account_id` в подписанной Flask
  session; подпись нужна для целостности состояния, а не для аутентификации.
- Каждый запрос проверяет, что выбранный профиль существует.
- Web UI по умолчанию слушает только `127.0.0.1`.
- Публикация в интернет или недоверенную сеть не поддерживается этой моделью и
  потребует отдельного решения об аутентификации до публикации.
- CSRF, безопасные пути, upload limits и server-side allowlists остаются нужны:
  они защищают локальные данные от ошибочных запросов и веб-страниц, открытых в
  том же браузере.

## Последствия

Положительные:

- интерфейс остаётся простым для семьи;
- не появляется лишняя парольная инфраструктура;
- техническое разделение данных можно тестировать по `account_id`.

Ограничения:

- любой человек с доступом к локальному UI может выбрать любой профиль;
- bind на внешний интерфейс без дополнительной защиты считается небезопасной
  конфигурацией и должен сопровождаться явным предупреждением.
