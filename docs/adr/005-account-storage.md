# ADR-005: неизменяемый account ID и account-scoped storage

- Статус: Accepted
- Дата: 20.08.2026

## Контекст

Отображаемое имя аккаунта сейчас является primary key, значением cookie и частью
пути `cv/<name>`. Переименование сложно, специальные имена опасны, а общий
`applications/` позволяет профилям перезаписывать dossiers друг друга.

## Решение

- Добавить аккаунту неизменяемый UUID `account_id`.
- `name` оставить изменяемым уникальным отображаемым именем.
- Все FK, jobs и artifacts связывать по `account_id`.
- Ввести настраиваемый `CV_AGENT_DATA_DIR`; пользовательские данные не вычислять
  относительно установленного Python package.
- Целевая структура:

  ```text
  <data-dir>/
    applications.db
    accounts/<account_id>/
      cv/
      applications/
      tmp/
    locks/
    backups/
  ```

- Любой путь строится централизованным resolver, затем проходит `resolve()` и
  containment check внутри account root.
- Миграция имён в UUID выполняется после backup, имеет dry-run/report и
  идемпотентна. Неоднозначные общие dossiers не распределяются автоматически.

## Последствия

- Профиль можно переименовать без переноса ссылок и конфликтов.
- Файловая и DB-изоляция используют один идентификатор.
- Потребуется миграция текущих `cv/<name>`, vacancies и applications.
