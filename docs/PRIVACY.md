# Конфиденциальность CV-Agent

Какие данные кандидата где обрабатываются и при каких условиях покидают
машину. Политика внешнего LLM зафиксирована в ADR-004.

## Где живут персональные данные

| Данные | Место | Покидает машину? |
|---|---|---|
| Документы профиля (CV и др.) | `data/accounts/<uuid>/cv/` (или legacy `cv/<имя>/`) | Нет, кроме явных случаев ниже |
| Структурированные данные кандидата (имя, адрес, контакты, языки) | SQLite `candidate_profiles` | Включаются в LLM-контекст при оценке и создании письма |
| Ключевые слова аккаунта | SQLite `accounts.keywords` | Нет |
| Оценки вакансий, досье, письма | SQLite + `data/accounts/<uuid>/applications/` | Нет |
| API-ключи Gemini/Groq | SQLite `accounts` (0600 на файл БД) | Только в запросах к соответствующему провайдеру |

## Когда текст уходит во внешний LLM

Основной провайдер — локальная Ollama. Если она работает на этом компьютере,
LLM-контекст обрабатывается локально; при настройке удалённого `OLLAMA_HOST`
он передаётся указанному серверу. Внешний провайдер используется, если
пользователь выбрал его модель либо Ollama недоступна и настроен fallback.
Дополнительного подтверждения передачи данных в формах нет.
Для обработки только на своей машине задайте локальный `OLLAMA_HOST`,
используйте Ollama и отключите `llm_fallback`.

В этом случае передаются: извлечённый текст документов в рамках purpose-бюджета
символов, структурированный профиль для оценки/письма и текст вакансии (title/description). Что именно войдёт в контекст,
видно заранее на странице профиля (preview по документам).

## Логи и телеметрия

- Внешней телеметрии нет.
- Лог заданий `data/logs/jobs.jsonl` содержит только метаданные (id, статусы,
  длительности, счётчики); error-поля проходят redact_sensitive (ключи и
  контактные шаблоны вырезаются).
- Хвост лога шага в SQLite ограничен; вывод CLI проходит ту же очистку.

## Удаление

- Удаление профиля (страница профиля, «Опасная зона») требует ввода имени:
  сначала создаётся архив-экспорт в `data/backups/profile-export-*`
  (копия БД, документы, отчёт), затем строки удаляются каскадом и каталоги
  профиля стираются. Архив остаётся на диске — удалите его вручную, если
  копия больше не нужна.
- Дефолтный профиль удалить нельзя (системный fallback).
- Retention: архив вакансий — `purge-archived --confirm` (applied не
  удаляются), завершённые задания с логами — `prune-jobs --confirm`.

## Запросы к источникам вакансий

Поиск выполняется к публичным API/страницам источников без аутентификации и
без персональных данных кандидата (только ключевые слова и локация).
Загрузка описаний вакансий — те же источники. Cookies/профили браузера не
используются.
