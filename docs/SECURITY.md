# Безопасность CV-Agent

Назначение документа — зафиксировать threat model, механизмы защиты и условия
безопасного изменения конфигурации. Основания: ADR-001 (локальная семейная
модель), ADR-004 (внешний LLM и согласие), ADR-005 (account storage).

## Threat model

Приложение предназначено для запуска владельцем на `127.0.0.1`. Атакующие,
рассматриваемые моделью:

- другой процесс/пользователь той же машины (ограниченно: права 0600/0700);
- содержимое вакансий и загруженных документов как недоверенный ввод
  (prompt injection, path traversal, опасные URL);
- случайное смешивание данных между семейными профилями.

Не входит в модель: целенаправленная атака члена семьи на чужой профиль.
Пароли и роли отсутствуют намеренно; профиль разделяет данные, а не защищает
их. Публикация в интернет или недоверенную сеть требует отдельного этапа
проектирования аутентификации (см. «Публикация в сеть»).

## Сессии и профили

- В подписанной Flask session хранится только внутренний `account_id` (UUID);
  отображаемое имя не участвует в путях и внешних ключах.
- Повреждённая, поддельная или устаревшая cookie отклоняется: имя профиля
  разрешается через DB на каждом запросе; неизвестный UUID — редирект на
  выбор профиля.
- Cookie: `HttpOnly`, `SameSite=Strict`, `Secure` при
  `CV_AGENT_SESSION_SECURE=1`, ограниченный срок жизни; logout только POST.
- Свободное переключение профилей сохраняется (семейный сценарий).

## Файловая система

- Единственный resolver `account_path(data_dir, account_id, kind)`:
  нормализация UUID, resolve(), проверка нахождения внутри accounts-root,
  запрет symlink на `accounts`.
- Uploads: расширение + MIME/сигнатура, лимиты 10 МБ/файл, 10 файлов, 50 МБ
  на профиль, запись во временный файл и атомарный rename после проверки;
  upload/delete не следуют по symlink.
- Права: `.env` и SQLite 0600, каталоги данных 0700; досье публикуются
  атомарно из временного каталога.

## Секреты

- Gemini/Groq ключи хранятся per-account в SQLite и никогда:
  - не возвращаются в HTML (только состояние и последние символы);
  - не попадают в subprocess environment (`ACCOUNT_KEY_ENVS` вычищается;
    CLI читает ключ текущего профиля прямо из DB);
  - не наследуются CLI-потомком из os.environ вместе с request-specific
    переменными (`CV_AGENT_USER`, `CV_AGENT_RUN_ID` и др.).
- Ключи и контактные данные удаляются из логов и сообщений об ошибках
  (`redact_sensitive`); структурный журнал заданий проходит ту же очистку.

## LLM

- Выбор модели: серверный allowlist option-id; произвольные base_url/
  api_key_env/model от клиента отклоняются; custom endpoint задаётся только
  в server config.
- SSRF-защита: разрешённые схемы/хосты, HTTPS для внешних провайдеров,
  запрет неожиданных loopback/link-local адресов для не-Ollama endpoint.
- При выборе внешнего провайдера или автоматическом fallback документы и
  вакансии передаются ему без дополнительного чекбокса согласия;
  фактическая модель и fallback отображаются пользователю.
- Промпты оборачивают недоверенные данные в delimiters с инструкцией
  игнорировать инструкции из содержимого; prompt-injection покрыт тестами.

## Команды и процессы

- Запуск CLI из web: server-side allowlist команд и типизированные аргументы
  (`_validated_job_steps`); неизвестная команда/аргумент отклоняются.
- Wall-clock deadline чтения stdout; timeout: terminate -> kill -> reap.
  Отмена прогона убивает группу процессов воркера тем же lifecycle.
- Ограниченный объём лога на job в SQLite; инкрементальная выдача по cursor.

## Публикация в сеть

Не поддерживается текущей версией. Минимальные требования до такого шага:
полноценная аутентификация (пароли/сессии), reverse-proxy с TLS, явный
пересмотр threat model в ADR-001, отключение `/health` наружу по решению
оператора, аудит зависимостей (`docs/OPERATIONS.md`).
